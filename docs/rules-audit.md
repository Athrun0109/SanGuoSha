# 对照官方规则的一轮体检(2026-08-19 ~ 08-21)

拿三国杀 wiki 的官方原文和 FAQ 逐条核对实现,查出来的问题和修法都记在这里。

**为什么要有这份记录。** 这一轮改的多半是"引擎不报错、一整局跑得完、只是结果不对"
的那类问题 —— 它们不会出现在任何堆栈里,只能靠拿外部权威文本逐条对才查得出来。
所以既要记**改了什么**,更要记**依据是哪一条**,以及**哪些地方是有意偏离官方的**。

对照用的语料在 [`docs/faq/`](faq/):27 张牌的官方效果原文 + 27 条牌 FAQ + 115 条武将 FAQ,
全部只取标准版(界限突破、国战、1V1、用间篇的文本都不一样,照着改等于换了个游戏)。

---

## 一、牌堆:106 → 104 张

**这是最底层、也是影响面最大的一条。** 拿官方《标准版游戏牌列表》逐格对之后发现:

| 问题 | 修法 |
|---|---|
| 多了【仁王盾】♣2(军争篇的牌) | 移出牌堆。**实现完整保留**,想开军争包加回 `DECK_TABLE` 即可 |
| 多了第二张【闪电】♥Q(军争篇) | 移出牌堆 |
| 【无懈可击】用了 EX 版的 ♦Q | 改回官方的 ♣K |
| 【八卦阵】放在 ♦2 | 改回官方的 ♣2 |
| 另外 7 张牌花色点数错位 | 归位(♥J杀→♣J、♦J杀→♦K、♥5桃→♥Q、♥K闪→♦2…) |

配比也从注释里写的 53/35/18 更正为官方的 **53/34/17**。

**为什么花色点数不是无所谓的细节**:判定看的就是它 —— 【闪电】判 ♠2~♠9、【乐不思蜀】判 ♥、
【八卦阵】判红色;转化技看花色 —— 武圣要红、倾国要黑、国色要 ♦;记牌器的整个概率模型
也建立在配比上。错了不会报错,只是所有相关概率都偏。

配套加了一条不变量测试:**官方牌堆相当于两副扑克,四种花色各 26 张、每个花色点数正好两张**。

**连带影响**:1v1 后手补牌的标定数据在新牌堆上重测过 —— 3000 局,不补 58.6% / +1 张 50.4% /
+2 张 45.2%(旧牌堆上量的是 61.0 / 53.1 / 45.4)。默认值 +1 不变,但从"偏先手 3 个点"
变成了基本持平。

## 二、引擎级:濒死结算的位置

**改动**:`game.damage()` 的顺序从

```
扣血 → DamageDone → DamageDealt → enterDying
```

改成

```
扣血 → DamageDealt(濒死之前)→ enterDying(求桃)→ 活下来才 DamageDone
```

**依据**:四个武将的 FAQ 是同一句话 ——「进入濒死状态时不可以发动,**除非被救回**」
(曹操【奸雄】、司马懿【反馈】、夏侯惇【刚烈】、郭嘉【遗计】)。而【麒麟弓】的 FAQ
要求恰好相反:「先弃掉坐骑牌(此时可以发动【枭姬】),**然后**才进入濒死状态」。

所以这两个时机**必须跨在濒死两侧** —— 它们不是同义词,只是过去两个都排在前面,
区分等于没落实。

**影响有多大**(2000 局 8 人局实测):

| 技能 | 受伤次数 | 其中致命且没救回 | 占比 |
|---|---|---|---|
| 反馈 | 1968 | 296 | **15.0%** |
| 遗计 | 1944 | 239 | **12.3%** |
| 刚烈 | 1938 | 157 | **8.1%** |
| 奸雄 | 5857 | 65 | 1.1% |

合计 **757 次技能发动**被这次改动取消掉。郭嘉的【遗计】里有八分之一是"死之前先给队友
送两张牌"—— 那两张不会随死亡弃置,是净赚。

## 三、牌的实现

| 牌 | 问题 | 依据 |
|---|---|---|
| 借刀杀人 | 挑受害者只查了射程,没查目标合法性 | 诸葛亮 FAQ:空城时**不可以**被指定为【借刀杀人】的【杀】目标 |
| 青龙偃月刀 | 第二张【杀】不重新验目标 | 诸葛亮 FAQ:过程中触发【空城】就**不可以**再对他使用 |
| 贯石斧 | 可以把自己弃掉 | 「可以弃自己装备区的牌,**除了【贯石斧】本身**」 |
| 方天画戟 | 条件写成"手牌数 ≤ 1" | 「必须是使用**自己最后一张手牌**」—— 手牌 0 张时旧写法照样给两个额外目标 |
| 五谷丰登 | 亮牌数按存活人数 | 官方是「等同于**目标角色数**」 |
| 闪电 | 造成伤害时不带牌 | 曹操【奸雄】因此收不到劈自己的闪电 |

【借刀杀人】和【青龙偃月刀】都改成走 `game.canTarget()` —— 引擎里那份唯一的目标合法性
判定,里面已经包含 `prohibitTarget` 查询。以前两处各自拼条件,本身就是隐患。

【方天画戟】为此把这张【杀】传进了 `slashExtraTargets` 查询的上下文 —— 以前那个查询拿到
的是空 ctx,只能看手牌数,所以才写成了那样。

## 四、武将技能

| 武将 | 技能 | 问题 | 依据 |
|---|---|---|---|
| 大乔 | 流离 | 先算攻击范围再弃牌,顺序反了 | 「计算是否在攻击范围内时,**不可以将弃置的牌算入**」 |
| 貂蝉 | 离间 | 没保证空城的诸葛亮排在"后选" | 「**必须指定诸葛亮为决斗的发起方**」 |
| 周瑜 | 反间 | 给出去的手牌是随机抽的 | 「牌的放置顺序**由周瑜决定**」 |
| 司马懿 | 反馈 | 能拿到伤害来源判定区的牌 | 「**判定区的牌不属于伤害来源的牌**」 |
| 关羽 | 武圣 | 拿装备当【杀】时没有自我限制 | 「需要装备提供的距离/攻击范围/武器技能时,不能将该装备打出」 |
| 刘备 | 激将 | 只实现了"打出",没实现"使用" | 10 条 FAQ 指向主动发起的那条路 |

### 【武圣】—— 新增 `game.asIfGone()`

判据是"**转化在前、出牌在后**":装备变成【杀】的那一刻就已经离开装备区了,所以判合法性时
要当它不在。落到引擎上就是一个作用域:

```ts
game.asIfGone(cards, () => ...)   // 把这几张牌当作已经不在场,再做判定
```

`statics(p)` 改成按装备槽位遍历(`equipSkills` 是 `Map<槽位,技能[]>`、`equips` 是
`Record<槽位,牌>`,同槽位能同时拿到牌和技能),被当素材的那张跳过。包了三个调用点:
`enumerateUsable` 的 `canUseNow`、多素材的 `firstCombo`、`selectTargets` 的目标枚举。

两个官方例子因此自动成立:♦【诸葛连弩】+本回合出过杀 → 无次数限制没了;
【贯石斧】(射程3)打距离 3 → 射程掉回 1。

### 【激将】—— 补上主动发起的那条路

官方文本"你需要**使用或打出**【杀】时"里的两个动词各是一条路:

- **打出** —— 原有的 `triggered`,挂 `AskingForCard`(被要求响应时)
- **使用** —— 新增的 `active`,进出牌菜单(主动发起一张【杀】,让蜀将提供)

关键是响应方走 `askForUse` 而不是 `askForCard` —— 前者只把牌交出来、**不弃置**,
由刘备去 `useCard`。这张【杀】的 `use.from` 是刘备,于是 6 条 FAQ 不用写一行代码就成立:
响应方的【铁骑】不触发、刘备自己的武器照常触发、【方天画戟】不触发、伤害和奖惩算刘备、
响应方能用自己的武圣/龙胆/丈八提供杀但用不了刘备的丈八。

`CANCEL_LIMIT` 从 2 提到 3:"没有蜀势力角色响应"也走 `return false`,而 FAQ 说
「没人响应后**可以更换目标继续发动**」。

## 五、有意偏离官方的地方

这几条是**明知不一致但保留**的,不要"顺手修好"。

| | 官方 | 我们 | 为什么 |
|---|---|---|---|
| 【离间】视为使用的【决斗】 | 可以被【无懈可击】抵消 | **不可以** | 按基础版规则,项目所有者明确要求 |
| 【离间】选人顺序 | 第一名视为使用【决斗】 | **先选的先出【杀】** | 界面上"先点的先动"更符合直觉;两者信息等价 |
| 【桃园结义】 | 对**所有角色**使用 | 跳过满血角色 | 不给满血角色白开一个必然无效的【无懈可击】窗口 |
| 【克己】 | 跳过弃牌阶段(手牌无上限) | **本回合手牌上限视为 32** | 见下 |
| 摸光牌堆 | 游戏结束、没有胜利者 | 不实现 | 有了克己上限之后几乎碰不到 |
| 【丈八蛇矛】两张同色牌当【杀】 | 有颜色(2红=红杀) | 无色 | 标准版里唯一看【杀】颜色的是【仁王盾】,已不在牌堆;开军争包再说 |
| 【突袭】 | 发动了就必须拿牌 | 可以退出改为正常摸牌 | 没有滥用空间(退出等于没发动) |

### 【克己】的 32 张上限

**房规,不是官方规则。** 实测(3000 局 8 人局)全场手牌峰值中位 8、p90 11,
**但最大出现过 66 张**,而那 66 张就是吕蒙。屯到那个量级有三个问题:

- **界面** —— 自己的手牌一行约放 12 张,40 张开始挤压战报区,100 张直接压垮布局
- **token** —— 104 张手牌时 L2 局面 1149 字、出牌阶段 **77 个选项**、题面 981 字,
  比正常手牌每次决策多烧约 1500 字,而且是每一次决策都多
- **体验** —— 那种局面对其他人基本是垃圾时间

所以把【克己】从"跳过弃牌阶段"改成"本回合手牌上限视为 32",走的是引擎现成的 `maxHand`
查询(那个键之前只有调用点、没有生产者)。**只在失控时才咬**:改完之后峰值中位和 p90
一个数都没动,3000 局里只有 10 局超过 32。

强度上不需要为此削他 —— 3000 局登场胜率 44.4%,和华佗 45.6%、张飞 43.4% 并列第一梯队。

## 六、顺带修的测试问题

改牌堆之后炸出三条,都是**靠特定牌局侥幸通过**的测试:

- `web.test.ts` 的手牌泄漏检查按"牌名+花色"字符串查,而牌堆里每个花色点数**有两张** ——
  视角自己手上有一张【杀♣9】、对手也有一张,直接误报泄漏。改成**数出现次数**
- `humanSeat.test.ts` 同样的问题:按 id 排除对手的牌,却按 label 查
- `webseat.test.ts` **挂死了整个文件**:`stage()` 里 0 号位的起手牌变了、多了一张
  【无懈可击】,五谷对其他目标结算时会来问他要不要无懈,而测试只提交了一次答案

第三条不是假阳性,是测试写得不够健壮 —— 以前能过纯属那副牌里恰好没有无懈。
