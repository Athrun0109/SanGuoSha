## 通用读法(三条,先看这个)

1. **「可测 ±Npt」那一列决定结论怎么写。**观测差远小于它 → 确实没变;观测差接近或超过它 → **样本不够,什么都不能说**。没有这一列,"p=0.25 所以没差别"是个陷阱。
2. **「兜底」那一行要先看。**模型答不上来时会回落到规则 AI。两组兜底率差得远的话,上面所有行都不能比 —— 那是可用性差异,不是能力差异。
3. **同局内对照的行为指标带混淆。**治疗组和对照组是同一局里的两支队伍,赢的一方资源多、场面顺,「收手」「误伤」几行会跟着好看。要下结论得按赢输分层(见 ③)。

## ① 加思考预算:行为没变,只多花钱

```
npm run metrics logs/bench-low -- --vs logs/bench-medium
```

```
指标                            bench-low     bench-medium   差异
还有牌却收手                 152/630 (24%)     99/428 (23%)   -1pt  p=0.71   可测 ±7pt
技能端上就用                  49/171 (29%)     28/129 (22%)   -7pt  p=0.17   可测 ±14pt
集火(瞎打=50%)              58/94 (62%)      46/73 (63%)   +1pt  p=0.86   可测 ±21pt
误伤队友                      2/158 (1%)       1/113 (1%)   -0pt  p=0.77   可测 ±4pt
──────────────────────────────────────────────────────────────────────
每次决策的推理量                  582.8tok         831.1tok   +43%
```

**结论**:`effort` 从 low 调到 medium,推理量 +43%、延迟 +30%,**所有行为指标都在噪声内**。

**边界**:这批只有 2 个 LLM 席位,且分处两队(各自的队友是规则 AI),所以它测不了"配合"类指标。32 局,seed 71000–71015。

## ② 把队友手牌放进 prompt:模型不看

```
npm run metrics logs/openhand -- --pools llm+open llm
```

一队互相看得见手牌,另一队照旧,**同一局里对打**,60 局(seed 73000–73059),治疗组按 seed 奇偶交替。

```
胜率(同局对手,配对)        34/60 (57%)   26/60 (43%)   +13pt  p=0.30   可测 ±18pt
集火(瞎打=50%)          238/386 (62%) 170/281 (60%)    -1pt  p=0.76   可测 ±11pt
──────────────────────────────────────────────────────────────────────
模型有没有用上队友的暗牌(翻它自己的推理原文)
  llm+open   3094 条推理   提到牌名 82 (3%)   逐字引用 2 (0.06%)
  llm        3020 条推理   提到牌名 71 (2%)   逐字引用 0 (0.00%)
```

**结论**:胜率方向对但**不显著**;主指标集火**纹丝不动**;而且模型的推理里几乎从不提队友的底牌 —— **说没说、做没做,两头都是空的**。

**注意**:"逐字引用"绝对值没意义(队友*打出*的牌本来就公开),只能看治疗组减对照组的差。

## ②b 换三种呈现方式:还是不看

```
for v in tail inline ask; do npm run metrics logs/attn-$v -- --pools llm+$v llm; done
```

同一批 seed(74000–74005),各 6 局,只改队友手牌**摆在提示词的哪里、写成什么样**:

| 写法 | 治疗组 | 对照组 | 差 |
|---|---|---|---|
| `tail` 局面块末尾(原写法) | 4/340 (1.2%) | 7/452 (1.5%) | −0.4pt |
| `inline` 并进角色表,和血量并排 | 8/387 (2.1%) | 2/299 (0.7%) | +1.4pt |
| `ask` 贴着题面,并写成**直接问它**的问句 | 8/408 (2.0%) | 8/371 (2.2%) | −0.2pt |
| **三批合并** | **20/1135 (1.8%)** | **17/1122 (1.5%)** | **+0.2pt,p=0.64,可测 ±1.5pt** |

**结论**:位置、格式、乃至"在它做决定的前一行直接问它"——**都不改变行为**。

**边界**:严口径的"逐字引用"六个组全是 0,但按基线推算 1135 条只期望 0.7 次,所以那个 0 只能排除"涨到 1% 以上"。真正有力的是宽口径那行的 ±1.5pt。

## ③ 换贵 10 倍的模型:响应倍数一样

```
npm run metrics logs/pro-inline -- --pools llm+inline llm     # 对比 logs/attn-inline
```

`deepseek-v4-pro`,提示词一字不改,seed / 配置与 `attn-inline` **逐项相同**,唯一变量是模型。

```
                治疗组          对照组       原始差    每千字推理提到次数   倍数
pro       15/287 (5.2%)   5/342 (1.5%)   +3.8pt    0.42 / 0.12        3.5x
flash      8/387 (2.1%)   2/299 (0.7%)   +1.4pt    0.34 / 0.10        3.4x
两者处理效应之差 +2.4pt,p=0.16,可测 ±4.7pt
```

**结论**:pro 绝对值更高,但它的推理平均 **123 字 vs flash 66 字** —— 话多一倍,提到任何一张牌的机会本来就多一倍。**按字数归一化后两个模型的倍数一致(3.5x vs 3.4x)**,并非它更会用信息。

## ④ 让一个模型同时操控整队(协作的上界):也赢不了多少

```
npm run bench -- --games=40 --jobs=8 --hive --llm=0,1,2,3 --seed0=73000 --out=logs/hive
npm run metrics logs/hive -- --pools llm+hive llm
```

同一个实例操控整队:信息完全共享、意图天然一致、**不需要任何沟通手段**。40 局(seed 73000–73039)。

```
胜率(同局对手,配对)     21/40 (53%)    19/40 (48%)    +5pt   p=0.75   可测 ±22pt
集火净值                      +7pt         +12pt        蜂群反而更低
误伤队友                 1/421 (0.2%)  12/385 (3.1%)          p<0.01 ★★
```

误伤按赢输分层(排除"赢了才好看"):

```
             赢的一方        输的一方
llm+hive   0/272 (0.0%)   1/149 (0.7%)
llm        3/240 (1.2%)   9/145 (6.2%)
```

**结论**:**"一个脑子开两只手"并不比两个各打各的赢得多**,而且集火还更少。唯一真实的差异是**不打自己人**(0.2% vs 3.1%,分层后依然成立 —— 那两只手本来就是同一个 agent)。

**这一条解释了 ②③:不是手段不行,是这个任务里协作本来就没多少可捞。**

**边界**:40 局只能排除 22pt 以上的效应,点估计 +5pt。

## ⑤ 改环境:一次改动的效果超过所有提示词干预之和

`openhand` 与 `hive` 两批的**对照组**(都是普通 `llm` 席位)配置完全相同 —— 同模型、同 effort、**同一批 seed(73000–73039)**,唯一差别是两批之间改了座次。这是一次天然实验:

```
旧座次 蓝红红蓝        40 局  集火 122/194 (63%)  瞎打基线 65%  净值  -2pt   误伤 20/390 (5%)
新座次 圆桌 0-1-3-2    40 局  集火 172/213 (81%)  瞎打基线 69%  净值 +12pt   误伤 12/385 (3%)
```

**改动内容**:三国杀把两件事绑在同一个圈上 —— **谁下一个行动**(回合顺序、下家、濒死求桃、AOE 结算)和**谁离谁近**(距离、射程)。2v2 里这两件事要的排布正好冲突:

- 回合顺序要「甲乙乙甲」,否则先手方凭空多 17pt(实测 58.6% vs 41.4%)
- 距离要「甲乙甲乙」,否则默认射程 1 只够得着一个敌人,集火在结构上不可能

拆开就都能满足:数组顺序(=回合顺序)不动,**只把物理圆桌另排成 0-1-3-2**(实现上只改了 `Game.distance()`)。

```
                    改前          改后
蓝队胜率           49.0%        48.9%     ← 平衡分毫未变,不需要补牌
两个敌人都够得着     38%          46%
【杀】菜单里出现队友  73%          30%     ← 误伤的结构性根因
```

验证命令:

```
npm run sim 2000 4 -- --mode=team2v2          # 平衡
npx tsx --test src/test/team.test.ts          # 距离性质(邻座都是敌人、队友在距离 2)
```

## ⑥ 计划器:少发 33% 请求(唯一的正面工程结果)

模型一次写好接下来几步,环境本地执行,只在计划前提被打破时才交还决策权。84 局全 LLM 席位统计:

```
决策总数        13,526
其中本地兑现     4,492  (33%)   ← 一个请求都没发
省下            13.3 小时墙钟

中断原因:换了回合 53%(自然到期,非失败) | 摸到新牌 19% | 真正的意外 17% | 选项对不上 9%
```

**代价**:计划会**放大错误的前提**。「AI 连打队友两张杀」案例里第二张就是按计划打的,而计划写于"目标是敌人"的错误认知下。少问模型 33%,代价是模型少 33% 的机会发现自己错了。

**实现教训**:计划第一步通常是模型这次**已经选掉**的动作,后面紧跟关于这一步的子问题(「为这张牌选目标」)。第一版把第一步丢掉了,子问题一来就判"计划外",**刚收到的计划当场作废** —— 某局 10 次中断全是这一类。

## ⑦ 一个诊断案例:先怀疑环境,再怀疑模型

现象:AI 连着两张【杀】打自己队友。三层原因叠加:

1. 模型推理原文写着要打**对面**残血的那个,从没打算打队友
2. 那个目标因技能免疫、另一个够不着 —— **唯一的合法目标就是队友**
3. 框架有"只剩一个合法解就直接替它选"的优化 → 模型**没被问**,无从知道意图落空

修法不是改提示词,是**把信息挪进选项文本**:`杀[♦8](只能指定 P2)`。回归测试见 `src/test/skillfix.test.ts`。

## 我们自己踩过的统计坑

| 坑 | 后果 | 修法 |
|---|---|---|
| 一队两席位同赢同输,却按席位数统计 | 60 局被当成 120 个独立观测,p 从 0.30 变 0.039,**看着就显著了** | 按(队伍 × 控制方式)每局只记一次;`src/eval/metrics.ts` 的胜负段 |
| 同局对手的胜率是**互补**的(34+26=60) | 双样本 z 检验又把样本量当成两倍 | 检测到互补就切单样本二项检验 |
| "配合好的队伍赢得多(+18pt)" | 反向因果:赢的队先打死一个敌人,之后攻击必然汇集 | 只统计两个敌人都活着的时刻 → **+1pt,p=0.95** |
| 集火率没减随机基线 | 敌人死剩一个时集火必然 100%,"打到残局"被读成"配合变好" | 按每次出手当时的存活敌人数逐笔折算期望重合 |
| 优化一个没验证过的代理指标 | 我们建了"集火率"当协作指标,后来发现**它根本不预测胜负** | 先验证指标与结果的关系,再拿它做优化目标 |

最后一条最值得警惕 —— 翻车时看板上一切正常。
