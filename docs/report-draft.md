# 我们以为 Agent 需要的四样东西,测下来都不需要

**—— 一个可复现对抗环境上的 Agent 评测,以及真正有效的那一件事**

---

## 一、动机:Agent 项目普遍无法验证自己的改动有没有用

做 agent 时我们反复撞上同一个问题:**改完不知道有没有变好。**

真实业务里几乎所有验证手段都不成立 —— 没有客观对错、没法把世界重置回改动前、跑一次很贵。于是"这版是不是更聪明"只能靠人看几个案例拍脑袋。结果就是:大家凭直觉往 agent 上加东西(加思考预算、加上下文、换更强的模型),**没人知道加了到底有没有用**。

所以我们先搭了一个**能测的环境**:客观胜负、seed 可复现、**\$0.05/局**、一晚上跑几十局,而且同时有协作、对抗和隐藏信息。

用的是三国杀。**游戏是手段不是目的** —— 我们要的是"能廉价地反复问同一个问题并得到可信答案"这个能力。(主流做法也是如此:DeepMind 用 Hanabi 研究有限沟通下的协作,Meta 用 Diplomacy 研究谈判。)

累计 **156 局 / \$7.50**。下面每个结论都出自这些对局,取数命令见附录。

---

## 二、结果:四个常见直觉,逐一证伪

| 你打算做的 | 我们怎么测 | 结果 |
|---|---|---|
| **① 加思考预算,agent 会更聪明** | 同一批 seed,`effort` low vs medium,32 局 | **行为完全没变**(最大差 −1pt,p=0.71)。代价:推理量 **+43%**、延迟 **+30%** |
| **② 把信息塞进 prompt,agent 就会用** | 一队互相看得见队友手牌,另一队照旧,**同一局里对打**,60 局 | **它不看。**3094 条推理中引用过队友底牌的只有 **2 条**(对照组 0 条),结果指标同样不动 |
| **③ 换更强的模型就能解决** | 换成贵 10 倍的同族大模型,提示词一字不改 | **响应倍数一样。**归一化掉"大模型话多"后是 3.5x vs 3.4x(差异 p=0.16) |
| **④ 让它们能协作就能赢** | 让**一个模型实例同时操控整队** —— 信息全共享、意图天然一致、无需沟通,40 局 | **不比各打各的赢得多**(53% vs 48%,p=0.75),集火反而更少 |

### 关于 ②:我们不甘心,又试了三种呈现方式

- **挪位置** —— 从局面描述末尾挪进角色表,和血量并排
- **变形式** —— 在它做决定的**前一行直接问它**:「队友手上有 X,这会改变你的选择吗?」
- **对照** —— 保持原样

**三种全部为零。**合并后治疗组与对照组差 +0.2pt(p=0.64,这批能测出 ±1.5pt)。

> **这条最值得带走:**「我们把数据放进 prompt 了」和「agent 用了这个数据」是两件完全不同的事。前者我们能控制,后者必须单独验证。

### 关于 ④:它同时解释了 ②③

④ 量的是**协作的上界**。上界既然只有 +5pt(且不显著),那么明牌、留言这些"半协同"手段没效果就不奇怪了 —— **不是手段不行,是这个任务里协作本来就没多少可捞。**

唯一真实的差异是**不打自己人**(0.2% vs 3.1%,按赢输分层后依然成立)。合理:那两只手本来就是同一个 agent。

## 三、真正有效的那一件事:改环境,不是改提示词

同一批 seed、同一个模型、同一份提示词,**只把桌上的座次换了个排法**:

```
                    集火净值(高于随机的部分)      误伤队友
旧座次                    -2pt                20/390 (5%)
新座次                   +12pt                12/385 (3%)
```

对比一下前面所有的信息类干预:明牌 **0**、三种呈现方式 **0**、贵 10 倍的模型 **0**。

**一次环境改动的效果,超过了我们所有提示词干预之和。**

原因是环境里藏着一个结构性约束:原座次下每个 agent 只够得着一个敌人,**"集火"在物理上就不可能发生**。我们却一直在提示词层面想办法让它们学会集火。

同一个教训在诊断案例里出现过一次。现象是「AI 连着两张攻击牌打自己队友」,看起来是模型太笨,查下来是:

1. 模型推理原文写着要打**对面**残血的那个,从没打算打队友
2. 那个目标因技能免疫、另一个够不着 —— **唯一的合法目标就是队友**
3. 框架有"只剩一个合法解就直接替它选"的优化 → **模型没被问**,无从知道意图落空

修法不是改提示词,是把信息挪进选项文本:`杀[♦8](只能指定 P2)`。

> **Agent 表现差,先查环境给了它什么,再查它笨不笨。**

## 四、另一个有效的做法:让 LLM 写"计划书"而不是逐步决策

模型一次写好接下来几步,**环境本地执行**,只在计划前提被打破时才交还决策权。

```
决策总数 13,526  →  其中 4,492 次(33%)本地兑现,一个请求都没发,省下 13.3 小时
```

**代价必须一起说:计划会放大错误的前提。**上面那个"攻击队友"案例里,第二张牌就是按计划打的 —— 而计划写于错误认知之下。少问模型 33%,代价是模型少 33% 的机会发现自己错了。

## 五、为什么我们能发现这些,而一般项目发现不了

结论本身不稀奇,**能得出结论的能力**才是这个项目真正的产出:

- **行为指标,不只是胜负。**胜负太贵太吵(1000 局才分辨得出 3 个百分点),而"会不会为防守留牌""削弱是否排在进攻前"二十局就有信号 —— 每局有几十个决策点。
- **同局内配对对照。**治疗组和对照组在**同一局里对打**,同一副牌、同一批角色、同样的运气全被消掉。
- **每个比例后面跟一列"最小可测差异"。**没有它,"p=0.25 所以没差别"是陷阱 —— 分不清"确实没变"和"样本不够什么都说不了"。
- **兜底率当守卫列。**模型答不上来会回落到规则 AI;两组兜底率差得远时,上面所有行都不能比。

### 我们自己踩过的统计坑(都会让内部看板说谎)

| 坑 | 后果 |
|---|---|
| 一队两个席位同赢同输,却按席位数统计 | 60 局被当成 120 个独立观测,p 从 0.30 变 0.039 —— **看着就显著了** |
| "配合好的队伍赢得多(+18pt)" | 反向因果:赢的队先打死一个敌人,之后攻击必然汇集。剔除后 **+1pt,p=0.95** |
| 优化一个没验证过的代理指标 | 我们建了"集火率"当协作指标,后来发现**它根本不预测胜负** |

最后一条最值得警惕 —— 在应用 ML 里这是最常见的翻车方式,而且翻车时看板上一切正常。

## 六、局限与下一步

**局限(必须说清):**

- 样本量不大(主实验 60 局与 40 局,呈现方式那组各 6 局);④ 只能排除 22pt 以上的效应
- 单一模型家族、单一任务,泛化性未验证
- "引用率"量的是模型**说没说**,不是**用没用** —— 只是结果指标同样为零,两头互相印证

**下一步:**既然协作上界已经量出来是低的,继续在"给 agent 更多队友信息"上投入的性价比很差。更值得做的是**沿着第三节那条线继续改环境** —— 把 agent 需要的信息挪进它必须逐条读完的选项里,而不是放进它可以略过的描述里。
